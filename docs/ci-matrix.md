## Editing rules

- `automated` is only for a job defined on main. The entry needs `job` with `source: main`, job names that exist in the workflow, and at least one `evidence` item of kind `ci`.
- A job that exists only on an unmerged PR is `pending`. It may name that job with `job.source: candidate` and `job.ref` naming the PR, or leave `job` out while the PR is still changing.
- An `automated` entry belongs to an enabled lane: test selection runs enabled lanes only, so the matrix cannot claim a job that is never selected.
- `pending` needs a `reason` and an `owner` or an `issue`. Owner and issue are empty for now and will be filled in.
- `not_applicable` and `skipped` need a `reason`.
- There is no manual-only status. A manual run is `evidence` of kind `manual` on a pending entry; it never makes the entry automated.
- `any` (in lane, model_profile, mode or topology) is allowed only on `not_applicable` and `skipped` entries. `none` is for entries that use no model or GPU.
- `model_profile` names a key of `model_profiles`, so a model changes in one place.
- A combination with no entry is not claimed; this is not a full Cartesian product.
